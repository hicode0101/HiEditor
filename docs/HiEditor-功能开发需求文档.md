## 0. 文档说明

### 0.1 目的与读者

本文档是 HiEditor 的**唯一需求基线**，用于在编码前把产品定位、功能行为、UI 视觉细节全部钉死，防止开发过程中理解跑偏。读者为：开发者、UI 实现者、测试/验收人员。

### 0.2 视觉与行为基准

1. **视觉基准**：两张参考截图。**基准截图一**（默认界面）：**Windows 11 新版记事本（2025 年，含 Markdown 格式工具栏）浅色主题 + 深色标题栏**形态，分辨率 1519×841（系统缩放 150%，逻辑窗口约 **1012×561**）；**基准截图二**（Markdown 形态）：Markdown 常用格式工具栏 + 所见即所得内容区，作为 Markdown 工具栏（UI-2.5）与 WYSIWYG 样式（UI-6）的视觉基准。文档未覆盖的细节按"贴近对应基准截图"处理。
2. **行为基准**：与新版 Windows 11 记事本一致（标签页、Markdown 工具栏、状态栏、会话恢复等）。已核实的公开行为：格式工具栏以 Markdown 语法落盘（Ctrl+B 包裹 `**…**`、Ctrl+I 包裹 `*…*`、Ctrl+K 插入链接、标题支持 H1–H6）。
3. **冲突裁决原则**：本文档与真实记事本行为有出入时，**一律以本文档为准**；文档未写的细节，按"贴近基准截图/新版记事本"处理，并在实现前补充进本文档。
4. **合规声明**：应用名、图标（笔记本风格）全部自绘自命名，**不使用微软图标/商标资产**；UI 布局与交互属于风格复刻。

### 0.3 术语表

| 术语 | 定义 |
|---|---|
| 逻辑像素 | 96 DPI（100% 缩放）下的 CSS 像素。本文所有尺寸均为逻辑像素 |
| 标签页/标签 | 标题栏中的文档标签，一个标签对应一个"文档缓冲区" |
| 缓冲区 | 一份在内存中打开的文档状态：文本内容 + 路径 + 脏标记 + 编码 + 换行符 + 撤销栈 + 视图状态 |
| 脏（未保存） | 缓冲区内容自上次保存后发生过修改，标签上显示"•" |
| 文档类型 | "Markdown"或非 Markdown，决定工具栏形态与编辑模式是否可用（联动规则见 FR-7.1） |
| 语言（高亮语言） | 按扩展名自动识别的语法高亮语言（纯文本/JSON/XML/…，见 FR-17），显示于状态栏段 3 |
| 插件 | 以文件夹为单位分发的能力扩展包：`config.json` + 原生扩展文件（dll/so/dylib）+ 可选前端资源（规范见附录 C） |
| 扩展点 | 宿主程序预留的能力注册接口（语言/高亮/格式化/工具栏/编辑视图等，EP-1~EP-8），插件经其接入 |
| 内置插件 | 随安装包发布于 `plugins/` 的官方插件：markdown、json、xml、plaintext、code（FR-18.8） |
| 编辑模式 | Markdown 文档的编辑形态：**所见即所得**（默认，内联渲染并直接编辑，UI-6）/ **源码模式**（原始 Markdown 文本 + 语法高亮） |
| 换行符 | CRLF（Windows）/ LF（Unix）/ CR（旧 Mac），状态栏显示为 `Windows (CRLF)` 等 |
| 会话 | 退出时保存的全部窗口/标签/未保存内容快照，用于下次启动恢复 |

## 1. 产品概述

### 1.1 产品定位

一款 **1:1 复刻基准截图 UI** 的跨平台轻量文本/Markdown 编辑器：秒开、简洁、以纯文本为核心，Markdown 格式工具栏为增值能力。不是 IDE，不做项目管理、语法高亮主题市场等重功能。

### 1.2 目标

1. UI 与基准截图逐像素级一致（几何 ±1px、颜色 ΔE≤3 的容差，见 11.3）。
2. 行为贴近新版 Windows 记事本，跨三平台体验一致。
3. 单文件场景性能优异（详见第 9 章指标）。

### 1.3 明确不做（v1 范围外）

Copilot/AI 集成、拼写检查、语法高亮**配色市场**（内置语法高亮属于 v1 范围，见 FR-17）、**在线插件市场与第三方插件签名校验**（本地插件系统属于 v1 范围，见 FR-18）、云同步、标签页拖出成独立窗口（P2，见附录 B）。

## 2. 窗口总体结构

### 2.1 区域划分

窗口自上而下共 4 个区域（尺寸为逻辑像素，与基准截图换算一致）：

```
┌────────────────────────────────────────────────────────────────────────────┐
│ A. 标题栏/标签条  高 40，背景 #202020                                        │
│ [应用图标] [标签:无标题 ●] [标签:无标题 ✕](激活) [+]          [—] [□] [✕]    │
├────────────────────────────────────────────────────────────────────────────┤
│ B. 菜单/工具行    高 40，背景 #f9f9f9，底边 1px #e5e5e5                      │
│ 文件 编辑 查看        [H1 ▾][列表▾][B][I][S][🔗][表格▾][A✎]        [📢][⚙] │
├────────────────────────────────────────────────────────────────────────────┤
│ C. 编辑区        背景 #ffffff，高度 = 窗口高 − 40 − 40 − 36                 │
│                     （设置页/查找条/横幅均覆盖在此区内）                      │
├────────────────────────────────────────────────────────────────────────────┤
│ D. 状态栏        高 36，背景 #f9f9f9，顶边 1px #e5e5e5                       │
│ 行 1, 列 1 │ 0 个字符 │ 纯文本 │····弹性空白····│ 100% │ Windows (CRLF) │ UTF-8 │
└────────────────────────────────────────────────────────────────────────────┘
```

- A、B、D 为固定高度；C 为唯一弹性区域。
- B 区工具组按激活标签语言切换：**默认工具栏**（UI-2.3 v1.6：仅字体/字号，适用于未声明自定义工具栏的所有语言）与**插件自定义工具栏**（如 Markdown 的 UI-2.5，由插件 config.json `toolbar` 声明驱动，联动规则 FR-7.1）。
- 激活标签背景色 = B 区背景色（#f9f9f9），视觉上激活标签与 B 区无缝衔接（这是截图的关键特征，必须实现）。
- 窗口整体：无边框自绘窗口，圆角 8px，投影 `0 8px 32px rgba(0,0,0,0.28)`；最大化的窗口圆角归零、无投影。

### 2.2 窗口规格

| 属性 | 值 |
|---|---|
| 默认大小 | 1012 × 561（与基准截图逻辑尺寸一致；用户调整后记忆，见 FR-10） |
| 最小大小 | 500 × 400 |
| 记忆 | 窗口大小/位置/最大化状态持久化，下次启动恢复 |
| 缩放适配 | 支持 100%–200% 系统 DPI，全部尺寸按逻辑像素×缩放渲染，字体清晰（矢量） |
| 启动状态 | 无会话时：打开 1 个窗口、1 个空白标签"无标题" |

### 2.3 三平台差异总表

| 事项 | Windows | macOS | Linux |
|---|---|---|---|
| 窗口装饰 | 无边框自绘（截图形态） | 隐藏原生标题栏，自绘标签条 | 无边框自绘（libadwaita/GTK CSD；Wayland 下经由装饰协议） |
| 窗口控制按钮 | 右侧 — □ ✕（截图样式） | **默认使用原生红黄绿交通灯（左侧）**，其余布局不变；设置项"复刻式窗口按钮（Windows 风格）"可切换为右侧 — □ ✕ | 右侧 — □ ✕（截图样式） |
| 快捷键修饰键 | Ctrl | ⌘（映射表见第 7 章） | Ctrl |
| 安装包 | NSIS 安装包（+可选 MSIX） | .dmg（含公证占位） | AppImage + .deb |
| 文件对话框 | 系统原生 | 系统原生 | 系统原生（GTK portal） |

除上表外，三平台 UI 完全一致。

## 4. UI 详细规格

### 4.1 A 区：标题栏 / 标签条（UI-1）

**UI-1.1 布局**：高 40。从左至右：应用图标 → 标签序列 → `+` 按钮 →（弹性空白）→ 窗口控制按钮组。

**UI-1.2 应用图标**：16×16 笔记本风格图标（自绘：白色纸页 + 顶部蓝色装订条 + 横线），距左 12px，垂直居中。

**UI-1.3 标签几何**：
- 标签高 32，顶部与 A 区顶部留 8px（即底部与 A 区底边齐平）。
- 单标签宽度：默认 **240px**；标签多时收缩，最小 **72px**；收缩到最小后整条横向滚动（见 UI-1.8）。
- 相邻标签间距 4px。
- 激活标签：背景 `--tab-active-bg`，**顶部两角圆角 8px、底部两角 0**（与 B 区无缝衔接）；文字 `--titlebar-text-active`。
- 非激活标签：背景 `--tab-inactive-bg`，四角圆角 4px；文字 `--titlebar-text`。
- 标签内部：左内边距 12px，标题文字 14px、超出可用宽度尾部省略号（可用宽度 = 标签宽 − 24 − 关闭按钮 20 − 8）。

**UI-1.4 标签右侧控件**（20×20 圆形热区）：
- 激活标签：**始终显示关闭 ✕**；hover 背景：深底时 `--dark-hover`，激活标签上为 `#e0e0e0`。
- 非激活未修改标签：默认不显示任何控件，hover 标签时显示 ✕。
- 非激活已修改（脏）标签：显示 **实心圆点 •（直径 6px，颜色同文字）**；hover 时圆点变为 ✕。
- ✕ hover 有 150ms 内的淡入。

**UI-1.5 `+`（新建标签）按钮**：32×32，图标 16px 居中，圆角 4px，hover `--dark-hover`。

**UI-1.6 窗口控制按钮组**（右侧贴边）：
- 每个按钮 **46 × 40**，无缝拼接，glyph 白色 1px 线宽。
- 依次为：最小化（—）、最大化/还原（□ / 双框）、关闭（✕）。
- hover：最小化/最大化按钮背景 `--dark-hover`；**关闭按钮背景 `#c42b1c`、glyph 白色**。
- 按下再 hover 最大化按钮弹出"贴靠布局"弹层为 **P2**，v1 不做。
- 应用处于"全屏"时最大化按钮 glyph 变为"还原"。

**UI-1.7 标签 tooltip**：hover 400ms 后显示，内容：已保存文件 = 完整路径；未保存 = "无标题（未保存）"；脏文件 = 路径 + "（有未保存更改）"。tooltip 样式：`#2b2b2b` 底、白字 12px、圆角 4px。

**UI-1.8 标签溢出**：宽度收缩到最小后出现横向滚动：在标签条上滚轮 = 横向滚动；最右侧出现半透明渐隐遮罩；**v1 不做"标签下拉列表"按钮（P2）**。

**UI-1.9 空隙交互**：双击标签条空白处 = 新建标签；拖拽标签到标签条内左右移动 = 重排序（拖拽中标签半透明，其余标签让位动画 150ms）。

### 4.2 B 区：菜单与工具行（UI-2）

**UI-2.1 布局**：高 40，背景 `--row-bg`，底部 1px `--row-divider`。三组内容：左侧菜单组（贴左，内边距 4px）、中部工具组（**在整行内水平居中**）、右侧按钮组（贴右，内边距 4px）。

**UI-2.2 菜单按钮**：`文件`、`编辑`、`查看`。高 32、水平内边距 12px、圆角 4px、字号 14px、间距 4px；hover `--light-hover`；**菜单展开期间保持高亮**。点击打开下拉菜单（见 UI-5.1）。

**UI-2.3 默认工具栏（v1.6 起 = 字体/字号 形态）**（自左至右，间距 8px，控件高 28px，水平居中）：

| # | 控件 | 外观 | 交互 |
|---|---|---|---|
| 1 | 字体标签 | 文本"字体"（12px，`--text-secondary`） | 纯标签 |
| 2 | 字体下拉 | 内联下拉（`.tl-select`），默认项"默认字体" | 选择后**仅对当前标签生效**（FR-2.14 per-tab）；选项：默认字体 / Cascadia Mono / Consolas / Courier New / 宋体 / 微软雅黑 / Arial |
| 3 | 字号标签 | 文本"字号" | 纯标签 |
| 4 | 字号下拉 | 内联下拉，初始值 = 全局默认字号（15px） | 选择后仅对当前标签生效；选项 10–36px 共 11 档；**行高按 1.5 × 字号联动缩放**，字号变大行距同步变大，行间不挤压 |

- 适用范围：**未声明自定义工具栏的所有语言**（纯文本、JSON、XML、代码等）。
- per-tab 规则（FR-2.14）：每个标签的字体/字号独立保存并随会话持久化；切换标签时下拉框与编辑区同步恢复该标签取值；未单独设置的标签跟随 设置 ▸ 文本编辑 ▸ 默认字号（全局默认值的修改对未单独设置的标签即时生效）。

### 4.3 C 区：编辑区（UI-3）

**UI-3.1 基础**：背景 `--content-bg`；文字 `--text-primary`；内边距：上 8 / 左 12 / 右 12 / 下 8。

**UI-3.2 光标与选区**：光标竖线 1.5px `--caret`，闪烁节奏 530ms 亮/530ms 灭；选区背景 `--selection-bg`（不透明覆盖文字，文字色不变）；多选（Ctrl+点击多光标）v1 不做。

**UI-3.3 输入法（IME）**：必须正确支持中文输入：组合窗口跟随光标位置、无闪烁、提交文本进入撤销栈、组合期间不触发字符统计抖动。此项为硬性验收项。

**UI-3.5 自动换行**：默认**关**（横向滚动）；查看菜单可切换（勾选态记忆于设置）。换行开启时按词边界折行（CJK 逐字可断），折行不影响"行号"逻辑行的定义。

**UI-3.6 滚动条**：覆盖式，宽 12px、圆角 6px，thumb `--scrollbar-thumb`，hover 加深，无箭头按钮；横向滚动条仅在自动换行关闭且内容超宽时出现；滚轮默认纵向，Shift+滚轮横向；**Ctrl+滚轮 = 缩放**。

**UI-3.7 长行**：不做视觉标记；渲染必须虚拟化（只渲染可视区 ± 缓冲行），10 万行/超长行（单行 1MB）不卡顿。

**UI-3.8 空文档态**：空白白底，无占位文字、无水印（与截图一致）。

**UI-3.9 Markdown 编辑形态**：所见即所得视图见 4.7 节（UI-6，覆盖本节度量）；源码模式沿用本节度量（等宽字体）+ FR-17 高亮。

**UI-3.10 语法高亮**：源码模式按 FR-17 的语言识别与配色表着色；高亮为纯展示层，不改变文本内容与复制结果；`纯文本` 语言不着色（保持截图形态）。

## 5. 功能需求

> 优先级标注：[P0]=v1 必须；[P1]=v1 尽量；[P2]=后续版本。未标注均为 P0。

### 5.1 标签页管理（FR-1）

- **FR-1.1** 新建标签：`+` 按钮 / 文件菜单 / Ctrl+N（Ctrl+T 为别名）。命名：首个 `无标题`，之后 `无标题 2`、`无标题 3`…（N 取当前未用到的最小序号，关闭后序号可复用）。
- **FR-1.2** 关闭标签：标签 ✕ / Ctrl+W / 中键点击 / 文件菜单 / 标签右键菜单。关闭最后一个标签 = 关闭窗口。
- **FR-1.3** 关闭脏标签时：默认弹 UI-5.7 确认；设置"关闭未保存标签时提醒=关"时不弹，内容静默保留进会话（与新版记事本一致）。
- **FR-1.4** 退出应用时**不逐个弹保存确认**：所有标签（含未保存内容）写入会话，下次启动恢复（FR-10.1）；"关闭未保存标签时提醒"设置不影响退出行为。
- **FR-1.5** 标签右键菜单（v1.5 变更）：右键任意标签弹出菜单，作用于被右键的标签：`关闭选项卡` / `关闭其它选项卡`（无其它标签时禁用）/ ─ / `保存`（非脏且已有路径时禁用）/ `另存为`；右键屏蔽 WebView 默认菜单。
- **FR-1.6** 切换：Ctrl+Tab / Ctrl+Shift+Tab 循环下一个/上一个（顺序 = 标签条视觉顺序）；Ctrl+PgDn/PgUp 别名。
- **FR-1.7** 拖拽重排（UI-1.9）；拖出窗口新建窗口为 P2。
- **FR-1.8** 每标签独立状态：路径、脏标记、编码、换行符、文档类型、缩放、编辑模式（所见即所得/源码）、滚动位置、光标位置（切换标签时全部恢复）。
- **FR-1.9** 窗口标题（任务栏/系统用）：`{文件名或无标题} - HiEditor`；脏时前缀 `*`。
- **FR-1.10** 同一文件允许在多个标签打开（不做合并/锁定）。

### 5.2 文件（FR-2）

- **FR-2.1** 打开：Ctrl+O / 拖放（FR-12）/ 系统关联打开。对话框起始目录 = 上次打开目录（每窗口记忆）。打开方式按设置"新标签页/新窗口"。
- **FR-2.2** 打开已打开的文件 → 定位到已有标签并激活（不新开）。
- **FR-2.3** 保存 Ctrl+S：脏才写盘；新文件（无路径）转另存为。写盘策略：先写临时文件再原子替换，防止损坏。
- **FR-2.4** 另存为 Ctrl+Shift+S：系统对话框，默认目录 = 当前文件目录，默认文件名 = 当前名；保存时按当前编码/换行符写盘；成功后标签改名。
- **FR-2.5** 全部保存 Ctrl+Alt+S：保存所有脏标签；遇无路径标签弹另存为，取消则中止后续。
- **FR-2.6** 最近文件：文件菜单子菜单最多 10 条（完整路径，去重按最近使用排序）+ `清除列表`；持久化。
- **FR-2.7** 外部变更（详见 BR-1/BR-2）：文件监听实时感知。
- **FR-2.8** 只读文件：可正常打开浏览（FR-14.2 横幅），保存失败转提示另存为。
- **FR-2.9** 大文件：≥ 设置阈值（默认 10MB）打开前确认 `文件较大 ({size})，仍要打开吗?`（`打开`/`取消`，勾选"不再提醒"可选）；> 512MB 拒绝并提示。
- **FR-2.10** 新建窗口 Ctrl+Shift+N：打开全新独立窗口（含 1 个空白标签）；窗口间状态独立，进程单实例（第二实例启动时唤起已有窗口并转发"打开文件"请求）。
- **FR-2.11** 打印 Ctrl+P：当前文档（含未保存修改）以等宽字体、`pre-wrap` 折行、`@page` 边距 2cm 的纯文本排版送入 WebView 原生打印对话框（支持"打印为 PDF"）；应用 UI 框架（标题栏/工具栏/状态栏）不参与打印；Markdown 渲染排版打印为 P2。
- **FR-2.14** 字体/字号 per-tab（v1.6）：默认工具栏的字体/字号选择**仅作用于当前标签**；标签未单独设置时回退全局默认字号（设置 ▸ 文本编辑）。取值随标签会话持久化（FR-10），切换标签即时恢复。字号变更时编辑区行高按 **1.5 × 字号**等比联动，任何字号下行间不挤压。

### 5.3 编辑（FR-3）

- **FR-3.1** 撤销/重做：Ctrl+Z / Ctrl+Y（Ctrl+Shift+Z 别名）。输入按"连打分组"合并（停顿 800ms 或光标移动/命令操作即断组）；栈深上限 250 步。撤销粒度覆盖：文本、格式包裹、表格插入、换行符/编码转换（FR-6.5）。
- **FR-3.2** 剪切/复制/粘贴：系统剪贴板；粘贴纯文本（**v1 不粘贴富文本/图片**）；剪贴板为空或无文本时 `粘贴` 禁用；无选区时 `剪切/复制/删除` 禁用。
- **FR-3.3** 删除：Delete 删除选区；无选区时删光标后一字符。
- **FR-3.4** 全选 Ctrl+A。
- **FR-3.5** 时间/日期 F5：在光标处插入 `HH:mm yyyy/M/d`（如 `14:23 2026/9/7`）。
- **FR-3.6** 覆盖模式：Insert 键切换插入/覆盖（P1；覆盖时光标显示为方块下划线）。
- **FR-3.7** 行列定义：行 = 逻辑行（1 基）；列 = 行内字符偏移 +1（1 基），CJK 字符计 1 列、Tab 计 1 列、换行符不计。
- **FR-3.8** 字符计数：按 Unicode 码点数（"字符"= 用户可见的一个码点）；换行符不计入。
- **FR-3.9** 大小写转换（v1.7）：编辑菜单提供 转大写 / 转小写 / 首字母大写其余小写，作用于当前选区；无选区时菜单项禁用、触发为无操作。首字母大写 = 每个单词（Unicode 字母序列）首字母大写、其余小写；转换计入撤销栈。

### 5.4 查找 / 替换 / 转到（FR-4）

- **FR-4.1** 查找 Ctrl+F：输入即查（防抖 150ms），定位首个匹配并选中；计数实时（`当前/总数`）；无匹配输入框红色描边。
- **FR-4.2** 匹配规则：默认不区分大小写；`Aa` 开启区分；**循环查找**（到末尾回开头）；不做正则/全词（v1）。
- **FR-4.3** 上一个/下一个：⬆⬇ 按钮、Enter/Shift+Enter、F3/Shift+F3。
- **FR-4.4** 替换 Ctrl+H：`替换` 替换当前并跳到下一个；`全部替换` 一次替换全部并计入撤销栈一步；完成后显示横幅式小提示 `已替换 N 处`（1.5s 自动消失）。
- **FR-4.5** 转到 Ctrl+G：见 UI-5.4；接受 1–总行数。
- **FR-4.6** 实现形态（v1.7）：面板基于 CM6 `@codemirror/search` 扩展内置面板（顶部置顶），支持区分大小写/正则/全词匹配选项、循环查找、`当前/总数` 计数、替换与全部替换（计入撤销栈）；面板文案经 phrases 按界面语言本地化（zh-CN/en-US）。查找/替换入口位于"搜索"菜单（编辑菜单之后）；F3/Shift+F3 跳转匹配、Esc 关闭面板。

### 5.5 查看 / 缩放（FR-5）

- **FR-5.1** 缩放范围 **30%–500%**；菜单步进 ±10%；Ctrl+滚轮连续（吸附到 1%）；字号 = 基础字号 × 百分比；行高同比例。
- **FR-5.2** 恢复默认 Ctrl+0 = 100%。缩放按标签记忆（FR-1.8），新标签默认 100%。
- **FR-5.3** 自动换行：查看菜单勾选项，切换即时生效；默认值来自设置。
- **FR-5.4** 状态栏显示开关（查看菜单）P1，默认显示。

### 5.6 编码与换行符（FR-6）

- **FR-6.1** 打开文件检测顺序：① BOM（UTF-8 BOM / UTF-16 LE / UTF-16 BE）② 严格 UTF-8 校验通过 → UTF-8 ③ 启发式检测（chardetng 类，结合平台本地代码页：中文 Windows 优先 GB18030/GBK）④ 全部失败 → 按本地 ANSI 以"替换字符"容错打开并横幅警告（FR-14.4）。
- **FR-6.2** 换行符检测：扫描全文，取**数量最多**的类型显示；三种类型计数进入状态栏提示（tooltip 显示 `CRLF: n, LF: m, CR: k`）。保存时**统一转换**为状态栏显示的类型（与经典记事本一致）；设置可开"保留原换行符"（默认关）。
- **FR-6.3** 新文件默认：编码 = 设置默认（UTF-8）；换行符 = 设置默认（Windows CRLF，三平台统一以对齐截图）。
- **FR-6.4** 状态栏编码显示映射：`UTF-8`、`UTF-8 (BOM)`、`UTF-16 LE`、`UTF-16 BE`、`ANSI`（tooltip 显示具体代码页如 `ANSI (GB18030)`）。
- **FR-6.5** 状态栏点击转换（UI-4.2）：换行符转换、编码转换（重新打开/另存）立即执行并**可撤销**（转换前整文快照入撤销栈一步）。
- **FR-6.6** "以其他编码重新打开"导致乱码风险时（当前非 UTF-8），对话框顶部黄条提示。

### 5.7 Markdown——所见即所得（FR-7，由内置插件 `markdown` 提供，见 FR-18）

- **FR-7.1** 文档类型与工具栏联动（v1.6 配置驱动）：语言按 FR-17.2 扩展名自动识别。**自定义工具栏由插件 config.json 的 `toolbar: { id }` 声明驱动**（附录 C）：宿主聚合"语言 → 工具栏 id"映射（仅统计启用且加载成功的插件），激活标签语言命中映射且前端存在对应容器（`toolbar-{id}`）时，B 区整组替换为该自定义工具栏（如 markdown 的 UI-2.5）；**未命中的语言一律显示默认字体/字号工具栏**（UI-2.3），不再存在禁用态按钮组。语言可经状态栏（UI-4.2 段 3，UI-5.10）手动覆盖，仅影响本标签的高亮/文档类型行为（含工具栏联动），不改文件内容。新建标签默认语言 = 设置（默认纯文本）。
- **FR-7.2** 编辑模式：Markdown 文档默认以**所见即所得**形态打开（UI-6）：标题/列表/表格/代码块/图片/任务列表等直接渲染为富文本样式并**可原地编辑**；可切换为源码模式（原始 Markdown 文本 + FR-17 高亮）。切换入口与规则见 FR-7.6；非 Markdown 语言无编辑模式概念（等同源码形态）。
- **FR-7.2a** 预览模式（v1.7 已实现）：md 标签在编辑区上方显示 **Edit / Preview** 分段切换控件；Edit = 源码 + 高亮（FR-17），Preview = marked 渲染的只读富文本视图（GFM：标题/粗斜体/列表/表格/代码块/引用/任务列表，主题化排版）。切换即时生效，缓冲区始终为源文本；非 Markdown 标签不显示切换条。所见即所得**原地编辑**引擎（Milkdown）仍在路线图。
- **FR-7.3** 所见即所得总则：**缓冲区文本永远是 Markdown 源文本**；所见即所得是其渲染编辑层，保存/另存/查找替换/字符计数/编码换行/状态栏等行为一律作用于源文本；渲染与编辑由 WYSIWYG 引擎承担（Milkdown/ProseMirror，见 10.1，随内置 `markdown` 插件的前端资源经 EP-4/EP-5 注册分发），与源文本双向即时同步。
- **FR-7.4** 源码模式语法插入规则（选区存在=包裹，无选区=插入占位并定位光标；重复触发=取消该格式；所见即所得模式下按钮行为见 FR-7.5）：
  - 标题下拉（H1–H6/正文）：改写当前逻辑行（多行选区则逐行）行首 `#` 前缀（正文=去前缀）。
  - 列表：无序 = 行首 `‑ `（`- `）；有序 = 行首 `1. `、`2. `… 连续编号；再次触发同类型 = 取消。
  - 粗体 `**文本**`（Ctrl+B）；斜体 `*文本*`（Ctrl+I）；删除线 `~~文本~~`（Ctrl+Shift+X）。
  - 链接 Ctrl+K：有选区 → `[选区](url)` 并选中 `url`；无选区 → `[链接文本](url)` 并选中 `链接文本`。
  - 表格（FR-7.7）。
  - 以上全部计入撤销栈一步。
- **FR-7.5** 所见即所得格式化行为：工具栏（UI-2.5）/快捷键即时作用于渲染结果，并实时序列化回 Markdown 源文本；toggle 类格式（粗体/斜体/下划线/删除线/行内代码/各类列表/引用）重复触发即取消；下划线序列化为 `<u>…</u>`；任务列表序列化为 `- [ ] ` / `- [x] `；撤销/重做与源文本一致（FR-3.1）。激活态：光标所在块为对应标题级别、列表/格式范围时按钮呈按下态；`H ▾` 按钮文字显示当前级别（正文显示 `H`，否则 `H1`–`H6`）。
- **FR-7.6** 编辑模式切换与插入交互：

### 5.16 JSON / XML 格式化（FR-16，由内置插件 `json` / `xml` 提供，见 FR-18）

- **FR-16.1** 入口：① 编辑菜单 `格式化 ▸`（§6）② 编辑器右键菜单（FR-15.1）③ 快捷键：JSON 格式化 `Ctrl+Shift+J`、JSON 压缩 `Ctrl+Alt+J`、XML 格式化 `Ctrl+Shift+L`、XML 压缩 `Ctrl+Alt+L`（macOS 映射见 §7）。实现位于内置插件 `json` / `xml` 的原生扩展文件（可复用 serde_json / quick-xml，见附录 C），宿主经扩展点 EP-3 调用，在后台线程执行，UI 不冻结。
- **FR-16.2** 作用范围：有选区时仅处理选区（须为完整合法的 JSON 值 / 平衡的 XML 片段，否则按 FR-16.5 报错）；无选区时处理全文。
- **FR-16.3** JSON 规则：
  - 严格按 RFC 8259 解析；键保留原顺序；数字字面量保留原样（`1.0`、`1e3` 不改写）；非 ASCII 字符不转义（中文原样保留）；字符串仅保留必要转义。
  - 格式化：缩进取设置"格式化缩进"（默认 4 空格）；冒号后 1 个空格；成员逐行换行；空对象 `{}` 与空数组 `[]` 不展开。
  - 压缩：移除全部结构外空白，形如 `{"a":1,"b":[1,2]}`。
  - `.jsonc`：允许注释参与解析校验；文档**不含**注释时可正常格式化/压缩；**含**注释时不改写文本，提示 `JSONC 含注释，暂不支持格式化`（P2 支持保留注释的重排）。
- **FR-16.4** XML 规则：
  - XML 声明 `<?xml … ?>` 独占首行；DOCTYPE、注释、CDATA 原样保留。
  - 含子元素的标签展开为多行并按层级缩进（缩进同"格式化缩进"设置）；**仅含文本的元素保持单行**（`<name>HiEditor</name>` 不拆行）；属性一律留在开始标签内，不逐行换行。
  - 文本节点内容、属性值、注释与 CDATA 内部的空白一律不修改；空元素保留自闭合写法。
  - 压缩：仅移除标签之间的空白与缩进，文本节点内容不动。
- **FR-16.5** 校验与错误：解析失败时**不修改任何文本**，弹出错误对话框（宽 420px，风格同 UI-5.4）：标题 `JSON 格式化失败` / `XML 格式化失败`；正文 = 中文错误消息 + 定位 `第 {line} 行, 第 {col} 列`（JSON 由字节偏移换算行列，XML 由解析器给出）；按钮 `确定`。
- **FR-16.6** 结果应用：替换目标文本并记为**一步撤销**；光标置于替换区域起点；行列/字符计数、高亮、状态栏随之刷新，并滚动到可见。
- **FR-16.7** 性能与确认：1MB 文档格式化 ≤ 1s；文档 ≥ 大文件阈值（默认 10MB）时先确认 `文件较大 ({size})，仍要格式化吗?`（`格式化` / `取消`）。
- **FR-16.8** 可用性：`JSON 格式化/压缩` 仅当前高亮语言 = JSON 时可用；`XML 格式化/压缩` 仅语言 = XML 时可用；其余语言（含纯文本）禁用。通过状态栏语言菜单（UI-5.10）切换语言即可启用对应项。

### 5.18 插件系统（FR-18）

> JSON、XML、Markdown、纯文本等各格式的**编辑/预览视图、格式工具栏、语法高亮、格式化**能力一律以插件形式提供；主程序为宿主，预留标准扩展点。目录结构、config.json schema、扩展点接口、加载流程详见**附录 C**。

- **FR-18.1** 目录与发现：插件默认全部位于**安装目录 `plugins/`** 下；**每个插件一个独立子文件夹**；宿主**每次启动自动遍历** `plugins` 的直接子文件夹，找到可解析的 `config.json` 即视为候选插件并进入加载流程。
- **FR-18.2** 插件构成与配置：每个插件目录包含 `config.json`（必需）+ 原生扩展文件（`bin/*.dll` / `*.so` / `*.dylib`，按平台取用）+ 可选前端资源（`assets/`）。`config.json` 配置：插件名称与唯一 id、版本、API 版本、**加载开关 `enabled`**、各平台入口文件路径，以及该插件的贡献声明（语言/高亮/格式化/工具栏/编辑视图/菜单）和**个性化配置项**（字段 schema 见附录 C.2）。
- **FR-18.3** 加载开关：`enabled=true` 的插件启动时**自动加载**并注册其贡献；`enabled=false` 的插件**忽略加载**（不加载动态库、不注册任何能力），设置页状态显示"已停用"。开关可在 设置 ▸ 插件 中修改，写回该插件的 `config.json`，**重启后生效**（热插拔 P2）。
- **FR-18.4** 扩展点（插入点）：宿主预留以下注册接口，插件经其接入；**内置能力（FR-7 Markdown、FR-16 格式化、FR-17 高亮）经由同一套扩展点注册，无特权通道**：
  EP-1 语言提供 · EP-2 语法高亮器 · EP-3 格式化命令 · EP-4 编辑视图（所见即所得/预览）· EP-5 格式工具栏 · EP-6 命令与快捷键 · EP-7 设置项 · EP-8 右键菜单（接口表见附录 C.3）。
- **FR-18.5** 生命周期与隔离：加载 → 注册贡献 → 就绪，退出时卸载；原生扩展文件必须为**稳定 C ABI 动态库**（必须导出的接口见附录 C.4）；单个插件加载失败或运行异常（panic/超时）只降级该插件（FR-14.7 横幅 + 标记"加载失败"），**不得影响宿主与其他插件**；格式化类命令调用超时默认 10s。
- **FR-18.6** 冲突与优先级：多个插件注册同一扩展名时，按加载顺序（子文件夹名字典序）先到先得；用户可用状态栏语言菜单（UI-5.10）对当前标签手动覆盖。
- **FR-18.7** 降级矩阵：停用/失败插件的能力按下表回退，界面不得出现空工具栏或报错弹窗堆叠：

| 停用/失败的插件 | 回退行为 |
|---|---|
| `markdown` | `.md` 以纯文本打开：无所见即所得、无 Markdown 工具栏、无 Markdown 高亮；查看菜单"编辑模式"禁用 |
| `json` / `xml` | 对应文件不着色，格式化/压缩菜单项与快捷键移除 |
| `plaintext` | 无可降级（即纯文本兜底） |
| `code` | 代码类文件不着色（仍可正常编辑） |
| 全部停用 | 编辑器退化为纯文本编辑器；默认界面（基准截图一）行为不变 |

- **FR-18.8** 内置插件清单（v1 随安装包附带于 `plugins/`）：`markdown`（FR-7 / UI-2.5 / UI-6）、`json`（JSON 高亮 + 格式化/压缩）、`xml`（XML 高亮 + 格式化/压缩）、`plaintext`（txt/log 等无高亮兜底）、`code`（FR-17.2 其余语言的高亮合集：HTML/CSS/JS/TS/Python/Java/C#/C/C++/Go/Rust/SQL/YAML/Shell/INI-TOML/Batch）。FR-17.2 语言-扩展名总表即上述插件贡献的并集。
- **FR-18.9** 用户插件目录（P1）：设置可指定额外插件目录（默认 `用户数据目录/plugins`），与安装目录合并扫描；注册同一插件 `id` 时用户目录优先。

## 8. 边界场景与行为规则（BR）

- **BR-1** 文件监听去抖：500ms 内多次磁盘变更合并为一次处理；写盘动作由本应用触发的（保存/另存）**不**触发重载提示（写入时间戳比对）。
- **BR-2** 监听失效（网络盘/权限）：降级为"保存前比对文件 mtime/哈希"，不一致走 FR-14.2。
- **BR-3** 混合换行符：显示多数派；保存统一转换（FR-6.2）；撤销栈含转换步骤。
- **BR-4** 超长单行（≥1MB）：虚拟渲染下不冻结；行列统计节流。
- **BR-5** 二进制文件（NUL 字节出现于前 8KB）：拒绝打开，提示 `无法打开：检测到二进制文件`。
- **BR-6** 文件名特殊字符/Unicode/空格：全链路支持；tooltip 与窗口标题原样显示。
- **BR-7** 路径过长（>260，Windows）：尽量以长路径 API 打开；失败走 FR-14.5。
- **BR-8** 会话/设置文件损坏：回退默认值，不崩溃，横幅提示设置已重置。
- **BR-9** 同步多窗口打开同一文件：各标签独立，互不联动（与 FR-1.10 一致）。
- **BR-10** 焦点策略：新标签/切换标签后焦点必须落回编辑区；打开菜单/浮层不丢失编辑区选区（返回时保持）。
- **BR-11** Markdown 所见即所得降级：文档 > 2MB 或 > 20,000 行时以源码模式打开并横幅提示 `文档较大，已使用源码模式`；用户可手动切换为所见即所得（自担性能）。

## 10. 技术选型与架构建议（推荐，评审点）

### 10.1 推荐方案：Tauri 2 + 系统 WebView 前端 + Rust 核心库

| 层 | 技术 | 职责 |
|---|---|---|
| 壳 | Tauri 2（Rust） | 无边框窗口、多窗口、单实例、文件对话框、菜单、全局状态、与系统交互 |
| 前端 | TypeScript + 原生 DOM（或 Preact，不引大型框架） | A/B/D 区自绘 UI、浮层、设置页（HTML/CSS 最易做到 1:1） |
| 编辑器 | CodeMirror 6 | 虚拟滚动、IME、撤销、查找、多语言语法高亮（成熟且可深度定制外观以贴合截图） |
| 编辑器（Markdown WYSIWYG） | Milkdown（ProseMirror 内核） | 所见即所得渲染与编辑、Markdown 双向序列化（FR-7 / UI-6） |
| 插件宿主 | Rust `hi-editor-plugin` crate + `libloading` + `abi_stable` | plugins 目录扫描、config.json 解析校验、动态库加载与 C ABI 绑定、扩展点注册表（EP-1~EP-8）、崩溃/超时隔离（FR-18 / 附录 C） |
| Rust 核心 crate `hi-editor-core` | 纯 Rust 库（不依赖 Tauri） | 文件读写（原子写）、编码检测（encoding_rs + chardetng）、换行符分析、文件监听（notify）、会话/备份持久化、设置存储、TTS（P2） |

**理由**：截图 UI 是 Fluent 风格的高度定制界面（自绘标签、模糊浮层、平滑动画），HTML/CSS 复刻效率与还原度最高；核心文件/编码/会话逻辑全部收拢在 Rust，符合"用 Rust 开发"的定位；三平台一致性好。
**主要风险**：Linux 上 WebKitGTK 渲染差异（需在验收机验证；备选降级 X11 行为）。

### 10.2 备选方案对比

| 方案 | 优点 | 缺点 |
|---|---|---|
| egui（纯 Rust，即时模式） | 单一二进制、渲染一致 | 富文本编辑/IME/中文输入支持弱，复刻 Fluent 细节成本极高 |
| iced / Slint（纯 Rust） | 无 WebView 依赖 | 自研文本编辑器（虚拟滚动+IME+双向文本）工作量约为方案 A 的 2–3 倍 |

> 结论：v1 采用 10.1；若评审坚持"零 WebView"，工期与风险需重估。

### 10.3 建议目录结构

```
HiEditor/
├─ docs/                      # 本文档等
├─ crates/
│  ├─ hi-editor-core/         # 文件IO/编码/换行/会话/设置/监听（纯 Rust，可单测）
│  ├─ hi-editor-plugin/       # 插件宿主：扫描/config.json 解析/动态库加载/扩展点注册表/隔离
│  └─ hi-editor-app/          # Tauri 壳：命令、事件、窗口管理
├─ ui/                        # 前端（TS/CSS/CodeMirror/Milkdown 集成）
│  ├─ src/components/         # titlebar / menubar / toolbar / statusbar / overlays / settings
│  ├─ src/editor/             # CodeMirror / Milkdown 视图、插件前端资源加载器
│  └─ src/plugin-runtime/     # 前端插件桥：动态加载 assets/main.js、贡献项装配
├─ plugins/                   # 内置插件源码与产物（markdown/json/xml/plaintext/code），随安装包分发
└─ resources/                 # 图标 SVG、i18n 资源、安装包资产
```

### 10.4 关键 Rust 依赖清单（建议）

`tauri 2`、`encoding_rs`、`chardetng`、`notify`（文件监听）、`serde`/`serde_json`（会话与设置、JSON 格式化）、`quick-xml`（XML 解析与格式化）、`tokio`（异步 IO）、`sys-locale`（本地代码页）、`arboard`（剪贴板兜底）、`tts`（P2 朗读）。前端按 FR-17.2 引入对应 CodeMirror 语言包（`@codemirror/lang-json`、`@codemirror/lang-xml` 等）实现语法高亮；Markdown 所见即所得采用 `milkdown`（ProseMirror 内核），公式渲染 `katex`，图表渲染 `mermaid`。插件宿主使用 `libloading`（动态库加载）与 `abi_stable`（稳定 C ABI 数据结构），详见附录 C。

### C.2 config.json 规范

必填字段：`id`、`name`、`version`、`apiVersion`、`enabled`、`entry`；其余可选。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 全局唯一标识（建议反向域名，如 `hieditor.json`） |
| `name` | string | 是 | 插件显示名称（zh-CN） |
| `version` | string | 是 | 插件版本（semver） |
| `apiVersion` | string | 是 | 目标宿主插件 API 大版本；与宿主不符则拒绝加载 |
| `enabled` | bool | 是 | **加载开关**：`true` 每次启动自动加载；`false` 忽略加载 |
| `author` / `description` | string | 否 | 作者 / 描述 |
| `entry` | object | 是 | 各平台原生扩展文件相对路径：`windows` / `linux` / `macos` |
| `frontend` | string | 否 | 前端贡献脚本相对路径（宿主前端按声明顺序加载） |
| `languages` | array | 否 | 语言贡献：`{ id, name, extensions[], highlight }`（EP-1/EP-2） |
| `formatters` | array | 否 | 格式化命令：`{ id, label, language, command, shortcut? }`（EP-3） |
| `toolbar` | object | 否 | 自定义工具栏贡献（v1.6 已消费）：`{ id }`；本插件声明的各语言激活时显示前端容器 `toolbar-{id}`，未声明语言用默认字体/字号栏（EP-5，如 markdown 的 UI-2.5） |
| `preview` | object | 否 | 编辑视图贡献：`{ engine: "wysiwyg" \| "readonly-preview" }`（EP-4） |
| `menus` | object | 否 | 菜单贡献：`{ context: ["format", …] }`（EP-8） |
| `settings` | array | 否 | 个性化配置项：`{ key, label, type: "select"\|"number"\|"bool"\|"string", options?, default }`，渲染于 设置 ▸ 插件 ▸ {插件名}；取值优先级 = 插件配置覆盖值 > 全局设置同名项 > 插件 `default` |

  "name": "JSON 支持",
  "version": "1.0.0",
  "apiVersion": "1",

  "description": "JSON 语法高亮、格式化与压缩",
  "entry": {
    "windows": "bin/hieditor_json.dll",
    "linux": "bin/hieditor_json.so",

  },

    { "id": "json", "name": "JSON", "extensions": [".json", ".jsonc"], "highlight": true }
  ],
  "formatters": [
    { "id": "json.pretty", "label": "JSON 格式化", "language": "json", "command": "pretty", "shortcut": "Ctrl+Shift+J" },
    { "id": "json.minify", "label": "JSON 压缩", "language": "json", "command": "minify", "shortcut": "Ctrl+Alt+J" }

### C.4 原生扩展文件要求

- 每平台一个动态库（`entry` 指定），**稳定 C ABI**，必须导出：

| 导出函数 | 作用 |
|---|---|
| `hi_plugin_meta() -> PluginMeta` | 返回 id / version / apiVersion（加载前校验） |
| `hi_plugin_init(host: *const HostApi) -> i32` | 初始化；宿主传入 API 函数表 |
| `hi_plugin_register(reg: *mut Registry)` | 向 EP-1~EP-8 注册本插件贡献 |
| `hi_plugin_command(cmd, ctx, out) -> i32` | 执行命令（格式化等），结果经回调/出参返回 |
| `hi_plugin_shutdown()` | 卸载前清理 |

- 宿主经 `libloading` 加载；插件内部必须捕获 panic（不得带崩宿主）；命令执行超时默认 10s，超时按失败处理并标记插件异常。
- `apiVersion` 与宿主不符：拒绝加载，状态"加载失败"，原因写入日志与设置页。

### C.5 启动加载流程

扫描 `plugins/*` 子文件夹 → 解析 `config.json`（缺失/损坏：忽略该文件夹并记日志）→ `enabled=false`：跳过（不加载动态库）→ 校验 `apiVersion` 与 `entry` 文件存在 → 加载动态库 → `hi_plugin_register` 注册贡献 → 就绪。任一步失败：标记"加载失败" + FR-14.7 横幅 + **继续加载其余插件**。

### C.6 分发与信任

内置 5 个插件（FR-18.8）随安装包放于安装目录 `plugins/`；用户可将第三方插件文件夹手动放入（v1 默认信任本机插件目录，签名校验为 P2）。
